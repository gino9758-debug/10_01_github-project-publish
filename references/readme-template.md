# README.md 模板

**先完整读取项目全部文件，再按此结构编写。所有内容必须与项目真实功能一致，不编造。**

```markdown
# <项目名称>

<一句话定位：这是什么>（<英文名/副标题>）

## 项目解决什么问题

<2-3 段说明：用户在实际使用中遇到的痛点是什么，本项目的核心价值是什么。避免空话，写具体场景和问题>

## 主要功能

<逐条列出核心能力，能用表格/列表就用。每个功能点必须对应项目真实实现>

## 安装方法

<按项目实际形态编写，例如 Skill 包的目录结构与导入方式：

### 方式一：<平台>导入（推荐）
<导入步骤>

### 方式二：<备选方式>
<步骤>

### 要求
- <依赖条件>
- <无需/需要安装第三方依赖的说明>
>

## 使用方法

<触发条件、使用步骤、交互规则，逐条写清楚>

## 输入输出示例

<给出 2-4 个真实示例：
**输入：** <用户原话>
**输出：** <结构化结果或响应>，格式与项目实际输出一致>
```

## 结构要点

| 章节 | 内容要求 |
|------|----------|
| 项目解决什么问题 | 痛点 + 核心价值，写具体场景 |
| 主要功能 | 与项目真实功能一一对应，表格优先 |
| 安装方法 | 目录结构、导入步骤、依赖说明 |
| 使用方法 | 触发条件、流程步骤、交互规则 |
| 输入输出示例 | 真实示例 2-4 个，格式与项目实际输出一致 |

## 编写规则

- 内容来源：项目文件原文（SKILL.md、代码、配置），**不编造功能、指标、引用**
- 语言：与项目主要语言一致（中文项目用中文）
- 排版：多用表格、列表、代码块，信息一目了然
- 完成后向用户展示要点，确认后再提交
